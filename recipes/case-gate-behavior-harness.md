# gate-behavior-harness

## 1. Executive Summary
This recipe runs an automated PASS/FAIL harness proving that role-scorer.mjs's
three phase gates -- liveness, timeline, and funding_recency -- behave as
multipliers on the composite score, not as additive votes. Ch.11/16 name
this exact failure mode ("the gate-as-vote bug") as the capstone's named build
failure: a gate that only discounts a score instead of zeroing it silently
produces wrong recommendations that look plausible. This harness constructs
synthetic roles with deliberately high sponsorship/fit votes (0.9/0.85), closes
one gate at a time, and asserts the resulting composite is <= 0.05 despite the
high votes. If a future code change ever turns a gate back into a vote, this
harness fails loudly with a non-zero exit code instead of letting a bad
recommendation ship silently.

## 2. Required Reads (before running)
- scripts/score/role-scorer.mjs -- the scorer under test; read the CONFIG.gate_zero
  constant (currently 0.05) before running, since the harness's assertions are
  pinned to that threshold.
- scripts/gates/fill-liveness-gate.mjs and scripts/gates/fill-funding-recency-gate.mjs
  -- the two gates this repo did not previously feed with real data before this
  contribution (see assignments/submissions/yuqinghannah/domain-justification.md
  in the Mode Build submission for that history).
- This recipe does NOT read or require data/ats/ or any private data -- all
  test roles are synthetic and clearly labeled SYNTHETIC-TEST-CO-*.

## 3. Phase Gates
1. Environment gate -- node --version must resolve and scripts/score/role-scorer.mjs
   must exist at the expected path. Failure path: harness exits 2 with a Usage message,
   never silently skips.
2. Composite-computation gate -- each synthetic role must produce a composite
   field in role-scores.json. Failure path: if role-scorer.mjs throws (as it
   did during Mode Build development -- see worked-run.md bug #2), the harness's
   execSync call throws uncaught and the process exits non-zero; it does not
   report a false PASS.
3. Gate-behavior gate (the harness's actual purpose) -- for every synthetic
   role with exactly one gate closed, composite must be <= CONFIG.gate_zero
   (0.05) despite votes of sponsorship=0.9/fit=0.85. Failure path: if any gated
   role's composite exceeds 0.05, the harness prints FAIL for that row and
   exits 1 -- this is the gate-as-vote bug being caught in the act.

## 4. Primary Stored Tools
- scripts/gates/gate-behavior-harness.mjs -- orchestrates the test: writes
  4 synthetic roles to data/examples/gate-behavior-harness-input.json,
  invokes scripts/score/role-scorer.mjs via execSync, reads back
  data/examples/role-scores.json, and asserts PASS/FAIL per role.
- scripts/score/role-scorer.mjs -- the component under test (pre-existing,
  extended during Mode Build work to add the funding_recency gate).
- No stored script exists yet for a fifth gate (visa timeline expiry edge
  cases beyond a simple 0/1 factor) -- flagged as a known gap, not fabricated.

## 5. Workflow
```
node scripts/gates/gate-behavior-harness.mjs
```
Internally: (1) write 4 synthetic roles to a fixed input file, (2) shell out
to role-scorer.mjs on that file, (3) parse the resulting role-scores.json,
(4) apply a PASS/FAIL assertion per role, (5) print a summary line and exit
0 (all pass) or 1 (any gate failed to zero the composite).

## 6. Output Contract
- Agent log: data/examples/role-scores.json -- full arithmetic trace per
  role (votes, weights, gate multipliers, gate_product, composite),
  machine-readable.
- Human report: data/examples/gate-behavior-harness-report.md -- Markdown
  table, one row per synthetic role, generated by role-scorer.mjs itself.
- Harness verdict: printed to stdout as PASS/FAIL per role plus a final
  summary line and process exit code -- this is the artifact a CI system
  would consume; it is never the same file as the human report (P5).

## 7. Verification Checks
- The control case (harness-all-gates-open) must NOT be gated -- its
  composite must exceed gate_zero and its recommendation must not be
  Skip. This proves the harness isn't just checking "does everything
  become zero" -- it isolates each gate's individual effect against a
  working baseline.
- Each of the three gated cases must independently show composite <= 0.05
  despite identical high votes -- proving the effect is caused by the closed
  gate, not by a coincidentally low vote.

## 8. Logging Rules
- Every harness run appends nothing automatically to logs/RUN_LOG.md --
  logging is a human-triggered action per this repo's existing convention
  (role-scorer.mjs and other scripts here do not self-log to RUN_LOG).
  The human running this recipe must add a RUN_LOG entry per the template
  in Section 9 of the companion recipe format, recording date, inputs
  (synthetic, not real companies), commands run, and pass/fail result.
- No personal or private data is ever written by this harness -- all inputs
  are synthetic and hardcoded in the script; nothing is read from data/ats/
  or private/.

## 9. Stop Conditions
- If role-scorer.mjs throws an exception (e.g., a missing field or a
  regression like the composite is not defined bug found during Mode Build
  development), the harness does not catch and suppress it -- the process
  exits non-zero and the raw stack trace is preserved, because a harness
  that hides its own crashes cannot be trusted to catch bugs in what it's
  testing.
- If any gated synthetic role's composite exceeds gate_zero, the harness
  reports FAIL for that specific role and exits 1 -- it never rounds a
  borderline result up to PASS.
